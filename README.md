# 自然輸入法 V11～V13 網頁相容修正

[English](README.en.md) · [下載外掛](https://github.com/kocpc001/natural-ime-v11-title-guard/releases/latest) · [問題分析](docs/diagnosis.zh-TW.md)

保留自然輸入法 V11～V13，在 X／Threads 原本的欄位輸入中文。這個小型瀏覽器外掛會縮短過長的分頁標題，避開讀取長視窗標題時的相容問題。v0.2.0 另加入 Telegram Web K 組字保護與 Gmail Gemini 初步相容修正。

**已知影響版本：V11、V12、V13。** 使用者已確認這三個版本都有同樣問題，並回報 X、Threads 的輸入問題已透過此處理解決。本專案公開的當機檔分析來自 V11；V12、V13 的確認來自使用者測試，尚未另行分析這兩版的二進位檔。

## 為什麼特定頁面打不出中文？

本次案例中，記事本與其他 Chrome 頁面正常，但某篇 X 貼文的回覆欄位收不到中文，甚至同一視窗的聊天側邊欄也受到影響。十份本機當機檔都指向 `OVIMGoing.dll` 讀取前景視窗標題的同一條路徑。

該程式的緩衝區到安全檢查值之間只有 **600 位元組（300 個 UTF-16 單位）**，呼叫 `GetWindowTextW` 時卻允許寫入 **600 個 UTF-16 字元**。案例中的視窗標題長度為 **313**，導致堆疊檢查失敗、輸入法背景服務終止。

X 會將貼文內容放進分頁標題，因此某些貼文會觸發此問題。這個外掛把超過 **180 個 UTF-16 單位**的標題縮短，保留標題開頭並加上 `… | V11`，為瀏覽器的視窗後綴預留空間。

這是針對長視窗標題的相容處理；不同輸入問題需要個別調查。詳見[診斷紀錄與限制](docs/diagnosis.zh-TW.md)。程式中的 `V11` 標題後綴及儲存庫／下載包名稱沿用首版命名，不表示只適用 V11。

## Telegram Web K：空白欄位組字被清空

已定位 Telegram 輸入事件處理程式在欄位只有空白時呼叫 `replaceChildren()`。自然輸入法 V11 開始組字時使用占位空白，網站清理空欄位會中斷組字。先打英文或數字有效，是因為欄位有了非空白內容，避開這條清理路徑。

v0.2.0 在組字期間保護該欄位的空白，確認文字後放行正常清空。原生 V11 已確認四次從空白欄位直接完成中文輸入，無須先打英文或數字；V12、V13 尚未個別驗證這項修正。支援範圍為 `web.telegram.org/k/`，不涵蓋 Telegram Web A 或桌面版。

## Gmail 側邊 Gemini：初步有效，仍需長期驗證

原先 Gemini 提問欄位間歇性無法輸入注音，同頁 Gmail 一般欄位正常。例如打「輸」（ㄕㄨ），可能只留下 ㄨ，最後變成「屋」。監看捕捉到占位空白被 Gmail／Gemini 的清空程式移除，組字隨後重新開始。

v0.2.0 提供**實驗性修正**：只在繁體中文介面的「向 Gemini 提問」欄位，攔住組字占位空白的 `input` 通知，保留原生 DOM 編輯，真正的中文字、英文和刪除正常傳給網站。V11 實測取得七次中文輸入事件，包含清空後重新輸入，使用者回報恢復正常。

**這是初步有效的相容處理，尚未證明所有間歇失效都已解決。** 部分早期紀錄也曾在移除空白後成功輸入，因此不能把所有失敗都定為同一根因。長時間使用、其他介面語言及 V12／V13 的 Gemini 行為仍待驗證。這兩種組字問題與 X／Threads 長標題當機不同，詳見[已知問題與驗證範圍](docs/known-issues.zh-TW.md)。

## 安裝

目前透過 GitHub 發布，採用載入未封裝外掛的方式。

1. 從 [Releases](https://github.com/kocpc001/natural-ime-v11-title-guard/releases/latest) 下載最新的 `natural-ime-v11-title-guard-v*.zip`，並解壓縮。
2. Chrome 開啟 `chrome://extensions`，開啟右上角「開發人員模式」。
3. 選「載入未封裝項目」，選取解壓縮後的 `natural-ime-v11-title-guard` 資料夾；此資料夾內應有 `manifest.json`。
4. 先保存草稿，再重新載入 X／Threads、Telegram 或 Gmail 分頁，讓外掛開始執行。
5. 在原本失敗的貼文回覆欄位，以原本的自然輸入法組字並確認；文字應能保留，不必發布。

若下載的是 GitHub 原始碼 ZIP，步驟 3 請改選其中的 `extension` 資料夾。

Edge 可用 `edge://extensions` 依同樣方式載入；其他支援 Manifest V3 的 Chromium 瀏覽器可能適用，但目前實際頁面測試僅涵蓋 Chrome。

## 外掛做了什麼？

- 在 X、Twitter、Threads 的 HTTPS 網頁頂層縮短長標題。
- 在 Telegram Web K 的實際訊息欄位，保留組字期間的占位空白。
- 在 Gmail 的繁體中文 Gemini 欄位，過濾占位空白的組字輸入通知。
- 短標題保留；長標題截短，並避免把 emoji 的 UTF-16 surrogate pair 切成半個。
- 監看 `<head>` 的標題變化，處理不重新載入的頁面切換。
- 在取得焦點、按鍵與開始組字時同步檢查標題長度。
- 全程在原欄位打字，無須額外輸入框或快捷鍵。

## 隱私與權限

X／Threads 腳本只讀取與修改分頁標題。Telegram 腳本會讀取指定訊息欄位的當前文字，判斷是否只包含組字空白；Gmail 腳本會檢查 Gemini 欄位的輸入事件資料，僅過濾一個組字占位空白。**這些文字與事件不會被記錄、儲存或傳送。** 程式沒有讀取剪貼簿、帳號或 Cookie，也沒有網路請求。

Manifest 只宣告上述指定網站的內容腳本，沒有 `tabs`、`clipboardRead`、`scripting` 等額外 API 權限。v0.2.0 新增 Telegram 與 Gmail 的頁面存取範圍；Chrome 會顯示相應網站存取權。Telegram／Gmail 腳本在 MAIN world 執行，以處理網站的組字事件；Gmail 腳本不查閱郵件內容或一般郵件編輯欄位。

原始當機檔、私人對話、郵件、錄影與診斷事件紀錄不包含在專案或發布包中。

## 更新與移除

更新時，以新版檔案取代原資料夾中的檔案，在擴充功能頁按外掛的重新載入按鈕，再保存草稿並重新載入網站。

停用／移除外掛後，重新載入網站會還原網站本身的標題與欄位事件處理。先前已經執行的內容腳本可能持續到該頁面重新載入為止。

## 開發與測試

外掛沒有建置步驟或執行期依賴。自動化 DOM 測試需要 Node.js 24 或符合 `package.json` 的版本：

```sh
npm ci
npm test
npm run package
```

測試包括短／長標題、emoji 邊界、動態替換標題、document_start 時尚未出現 head、同步輸入事件檢查，以及欄位內容和輸入事件是否保留；另驗證 Telegram／Gemini 的占位空白、正常清空、其他欄位與動態替換欄位。DOM 測試不會操作 Windows 自然輸入法，不能代替實際輸入法驗證。

發布包與 SHA-256 在 `dist/`。目前版本的變更見 [CHANGELOG](CHANGELOG.md)。

回報問題時，請提供自然輸入法／瀏覽器版本、網站、分頁標題長度與重現步驟。避免公開當機檔、帳號資料或私人輸入內容。
